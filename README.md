# ZenFlow

CRM нового поколения для массажистов, SPA и специалистов телесной терапии.
Рабочее пространство специалиста — быстро, красиво, интуитивно.

## Стек

- React 18 + Vite
- React Router (роутинг между экранами)
- Tailwind CSS (утилиты + CSS-переменные для темы)
- lucide-react (иконки)
- Fraunces / IBM Plex Sans / IBM Plex Mono (шрифты)

## Запуск

```bash
npm install
npm run dev
```

Откроется на `http://localhost:5173`.

Сборка для продакшена:

```bash
npm run build
npm run preview
```

## Структура

```
src/
  theme.jsx              — контекст светлой/тёмной темы (единая точка правды)
  index.css              — CSS-переменные палитры, шрифты, анимации
  App.jsx                — роутинг
  components/
    BottomNav.jsx         — нижняя навигация (5 пунктов)
    ThemeToggle.jsx       — кнопка переключения темы для хедеров
    Switch.jsx            — переключатель для настроек
  screens/
    Dashboard.jsx         — главная: «Дыхание дня», следующий клиент, таймлайн
    Calendar.jsx          — день/неделя, перенос записи, цветные услуги
    ClientCard.jsx        — профиль клиента, рейтинг, история/оплаты/заметки/фото/рекомендации
    AppointmentForm.jsx   — создание/редактирование записи, повтор, отмена, завершение
    Finance.jsx           — доход/расход/прибыль/средний чек, график по дням
    Settings.jsx          — рабочее время, услуги, уведомления, тема
```

## Дизайн-система

Палитра и типографика заданы CSS-переменными в `src/index.css`
(`--paper`, `--surface`, `--moss`, `--clay` и т.д.), переключаются
классом `.dark` на `<html>`. Все экраны используют только эти
переменные — новый цвет темы меняется в одном месте.

Принципы интерфейса:
- максимум 5 пунктов в нижнем меню;
- любое действие — не больше 3 кликов;
- одинаковое поведение форм на всех экранах;
- крупные кнопки для работы с телефона;
- светлая и тёмная тема на всех экранах.

## Данные

Клиенты (список, карточка, заметки) теперь берутся из реальной базы —
см. раздел «Backend» ниже. Записи, услуги и финансы пока остаются
мок-данными внутри экранов (`Dashboard.jsx`, `Calendar.jsx`,
`AppointmentForm.jsx`, `Finance.jsx`, `Settings.jsx`) — следующий
логичный шаг — перевести и их в Supabase по той же схеме, что и клиентов.

## Backend

Данные клиентов хранятся в **Supabase** (Postgres + автогенерируемый REST API).
Схема таблиц — в `supabase/schema.sql`, выполняется один раз через
Supabase → SQL Editor → Run.

Локально и на Vercel нужны переменные окружения (см. `.env.example`):

```
VITE_SUPABASE_URL=...
VITE_SUPABASE_ANON_KEY=...
```

Локально — файл `.env` в корне проекта (не коммитится, см. `.gitignore`).
На Vercel — Project Settings → Environment Variables.

`src/lib/supabaseClient.js` — единственное место, где создаётся клиент.
`src/data/clients.js` — единственное место, где экраны обращаются к базе
(getClients, getClientById, getHistory, getPayments, getNotes, addNote,
getRecommendation). Если бэкенд когда-то сменится — переписывать нужно
будет только этот файл, не экраны.

Таблицы: `clients`, `client_history`, `client_payments`, `client_notes`,
`client_recommendations`. Row Level Security включён с политикой
«разрешить всё» — временно, до появления авторизации специалиста.
